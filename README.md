# OM SAI Interiors & Construction — Full Website

A complete, deployable website: a responsive HTML/CSS/JS frontend and a
real FastAPI + SQLite/PostgreSQL backend, covering everything in the
spec — login/signup, home, services with 8 categories and 34
sub-services, booking, quotations, bills & invoices, UPI-only
payments with screenshot verification, about, contact, and a full
admin dashboard (users, bookings, service catalogue, payments,
quotations, invoices, gallery, analytics).

```
omsai/
├── frontend/     — open this in a browser / deploy as a static site
└── backend/      — FastAPI + JWT auth + SQLite (Postgres-ready)
```

## Quick start (2 terminals)

**Terminal 1 — backend**
```bash
cd backend
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn main:app --reload --port 8000
```

**Terminal 2 — frontend**
```bash
cd frontend
python3 -m http.server 5500
```
Open **http://localhost:5500**. The frontend auto-detects `localhost`
and talks to the backend on port 8000 — no config needed for local dev.

> Opening `frontend/index.html` directly by double-clicking (a
> `file://` URL) also mostly works since there's no build step, but a
> local static server (as above, or the VS Code "Live Server"
> extension) is recommended so relative paths and the browser's
> fetch/CORS behavior work exactly like production.

## What's implemented

- **Auth**: signup, login, JWT sessions (7-day expiry), forgot-password
  scaffold, protected pages that redirect to login when needed.
- **Services**: 8 categories exactly as specified, each with its
  sub-services on one page (no extra page per sub-service), pulling
  live data from the backend with a bundled fallback so pages never
  break if the API is offline.
- **Booking**: authenticated booking form + personal booking history
  with live status.
- **Quotations**: request form + list showing admin-provided quotes
  once sent.
- **Bills & Invoices**: itemised invoices generated by admin, viewable
  and printable per customer.
- **Payments**: UPI / Google Pay / PhonePe / Paytm / Net Banking only
  (no cards, as specified), QR placeholder, transaction ID +
  screenshot upload, verification workflow, payment history.
- **Admin Dashboard**: user management, booking approval workflow,
  full service-catalogue CRUD (categories + sub-services), payment
  verification, quotation replies, invoice generation, gallery
  uploads, and an analytics panel (users, bookings, revenue, popular
  services).
- **Responsive design** throughout, with a mobile nav drawer and a
  distinct visual identity (see "Design" below) rather than generic
  Bootstrap styling.

## Design

The visual direction is a "site dossier" — a blueprint / measuring-tape
motif (see the brass tick-marks under headings) in warm ivory, aged
brass and deep emerald, with a serif display face (Fraunces) paired
with Work Sans and a monospace face for prices and data. Service
sub-pages are laid out like catalogue spec sheets rather than generic
cards. All imagery is pulled live and on-topic from LoremFlickr by
keyword (free, no API key) — see the note on images below.

## About the images

Every photo on the site is a **verified, individually-checked Unsplash
photo** (free license, hotlinked from `images.unsplash.com`) — kitchen
photos on the Kitchen Design section, a real window photo for UPVC
Work, real plumbing-tool photos for Plumber Work, and so on. A handful
of visually-similar sub-services within the same category (e.g. all
five Electrician sub-services) intentionally share one verified photo
rather than risk pulling in an unrelated one.

A prior draft of this project used LoremFlickr keyword URLs, which
turned out to be unreliable (Flickr blocked LoremFlickr's API for
most of 2025–2026) and served unrelated placeholder images — that has
been replaced everywhere with the verified Unsplash photos described
above. Swap in your own project photography before a real launch:

- Frontend fallback data: `frontend/js/services-data.js` (the `IMG`
  constants at the top, and the `img:`/`hero:` fields)
- Backend-seeded copy: `backend/seed.py` (the `_LIVING_ROOM`,
  `_KITCHEN`, etc. constants — used once, on first run, to populate
  the database; after that, edit images from the Admin Dashboard →
  Services tab instead)
- Home page hero/gallery images: inline `<img>` tags in `index.html`
  and `about.html`

## Deploying

- **Frontend**: any static host — Netlify, Vercel, GitHub Pages,
  Cloudflare Pages, S3+CloudFront, or your own Nginx. Just update the
  production branch in `frontend/js/config.js` with your backend's
  real URL first.
- **Backend**: see `backend/README.md` for PostgreSQL setup, file
  upload storage, and ASGI hosting notes (Render, Railway, Fly.io, a
  VPS, etc).

## Notes & honest caveats

This is a complete, working scaffold — every button, form and admin
action is wired to a real backend endpoint and was tested end-to-end
before packaging (signup → login → book → admin-approve →
invoice → pay → verify all work). Before a real public launch you'd
still want to: add production secrets, swap SQLite for Postgres, wire
up transactional email (the forgot-password flow is a stub), add rate
limiting, and replace the LoremFlickr placeholder photography with
your own project photos.
